Дослідницький проєкт з аналізу просторово-часових закономірностей оголошення повітряних тривог в Україні (березень 2022 – вересень 2026 року) та короткострокового прогнозування початку нової тривоги у спокійні години.

Проєкт поєднує **описову аналітику часових рядів (Етап 1: RQ1–RQ3)** та **моделювання машинного навчання (Етап 2: прогноз стартів у вікні $[T, T+1\text{h})$)**.

## 🤖 Машинне навчання: Прогнозування початку тривоги

### Постановка задачі та набори ознак (A, B, C та пост-хок C')
* **Момент прогнозу $T$:** регулярна годинна сітка в UTC (`timestamp_utc`).
* **Кондиціонування на спокій:** у матрицю `ml_features_hourly.parquet` включаються виключно ті рядки, де на момент $T$ в області немає активної тривоги (`is_active_T == 0`). Всього `797 428` спокійних людино-годин по 24 областях (`0` дублікатів за `(timestamp_utc, oblast)`).
* **Цільова змінна (`target_onset_next_1h`):** $y_T = 1$, якщо нова тривога в області починається у піввідкритому інтервалі **$[T, T + 1\text{h})$** (у коді: `k_onset = int(s_sec // 3600)`).
* **Ієрархія наборів ознак (усі рахуються строго з даних до моменту $T$, `closed="left"`, на повній годинній сітці до фільтрації спокою):**
  * **Набір A (Time, Burden & Train Cluster — 10 ознак):** `hour_sin`, `hour_cos`, `day_of_week`, `is_weekend`, `month` (за `Europe/Kyiv`), `burden_last_6h`, `burden_last_24h` (частка активних годин у $[T-6\text{h}, T)$ та $[T-24\text{h}, T)$), та One-Hot індикатори кластера з Train (`cluster_1_low_activity`, `cluster_2_medium_activity`, `cluster_3_high_activity`).
  * **Набір B (A + Spatial at $T$ — 13 ознак):** Набір A + миттєвий стан сусідніх областей рівно в момент $T$: `neighbors_active_count`, `neighbor_any_active`, `neighbor_active_ratio`.
  * **Набір C (B + Adaptive & Spatio-Temporal Memory — 22 ознаки, основна передреєстрована конфігурація):** Набір B + 9 адаптивних та просторово-часових ознак з минулого:
    * `adaptive_rate_7d`, `adaptive_rate_14d`, `adaptive_rate_30d` — ковзна частота стартів у цій області за попередні 168, 336 та 720 годин (`closed="left"`).
    * `national_active_count` — загальна кількість областей України з активною тривогою рівно в момент $T$.
    * `onsets_last_24h` (Варіант А) — сума годин зі стартами тривог в області за $[T - 24\text{h}, T)$ (`closed="left"`).
    * `hours_since_last_alert` — кількість годин від останнього відомого `finished_at <= T` в області до моменту $T$ (`clip(upper=720.0)`).
    * `neighbors_active_lag_1h`, `neighbors_active_lag_2h`, `neighbors_active_lag_3h` — кількість активних сусідів у моменти $T-1\text{h}$, $T-2\text{h}$, $T-3\text{h}$ на повній сітці.
  * **Набір C' (`FEATURE_SET_C_PRIME`: B + Adaptive & Neighbor Lags Only — 19 ознак, пост-хок експеримент):** Набір B + `adaptive_rate_7d/14d/30d` + `neighbors_active_lag_1h/2h/3h` (**без** `national_active_count`, `hours_since_last_alert` та `onsets_last_24h`, які зазнали найбільшого зсуву розподілу між Train і Test).

> **⚠️ Пост-хок позначка (Post-Hoc Disclosure):**  
> Головне порівняння було заздалегідь визначене як **Набір C (`Set C`) проти адаптивного бейзлайну (`Adaptive 14-day Rolling`)**. Вибір **`Set B`** як найкращої моделі за PR-AUC, а також конструювання та оцінка редукованого набору **`Set C'`** зроблено **після перегляду результатів на Test і є пост-хок (post-hoc)**. Усі гіперпараметри та пороги $p^* = \arg\max F_2$ для всіх моделей (включно з `Set C'`) підбиралися виключно на Validation без жодного використання Test.

### Хронологічний поділ вибірки (UTC, з 2-годинним буфером Embargo)
* **Train:** `2022-03-15` – `2024-04-30` (`410 150` спокійних годин, `33 240` стартів, базова частка **$8.10\%$**).
* **Validation:** `2024-05-01` – `2025-05-31` (`190 195` спокійних годин, `19 342` старти, базова частка **$10.17\%$**). Усі гіперпараметри, рання зупинка та пороги $p^* = \arg\max F_2$ налаштовуються виключно на Validation.
* **Test (повний):** `2025-06-01` – `2026-09-07` (`197 083` спокійних годин, `464` доби, `20 250` стартів, базова частка **$10.27\%$**):
  * **Підперіод Test до `2025-08-01` (`2025-06-01` – `2025-07-31`):** `28 929` спокійних годин, `62` доби, `2 782` старти (базова частка **$9.62\%$**).
  * **Підперіод Test з `2025-08-01` (`2025-08-01` – `2026-09-07`):** `168 154` спокійних години, `403` доби, `17 468` стартів (базова частка **$10.39\%$**).
* **Останні 60 днів (підмножина Test):** `2026-07-09` – `2026-09-07` (`23 646` спокійних годин, `2 992` старти, базова частка **$12.65\%$**).

## 💡 Інтерпретація результатів, зсув розподілу ознак та пост-хок аналіз

1. **Заздалегідь зафіксоване головне порівняння (`LightGBM Set C` проти `Adaptive 14-day Rolling`):**
   * **На повному Test (`2025-06` – `2026-09`):** `LightGBM (Set C)` статистично значуще перевершує `Adaptive 14-day Baseline`:
     * **$\Delta \text{PR-AUC} = +0.0297$**, 95% CI **$[+0.0220, +0.0373]$** (`0.3329` проти `0.3031`, відносний приріст **$+9.8\%$**).
     * **$\Delta F_2 = +0.0249$**, 95% CI **$[+0.0189, +0.0304]$** (`0.5551` проти `0.5299`, відносний приріст **$+4.7\%$**).
     * **Precision при фіксованому `Recall = 78.23%`:** **26.25%** у `LightGBM (Set C)` проти **23.14%** у адаптивного бейзлайну ($+3.11$ в.п.).
   * **На останніх 60 днях (`2026-07-09` – `2026-09-07`):** `LightGBM (Set C)` **не дає статистично значущої переваги** над `Adaptive 14-day Baseline`:
     * За **PR-AUC** різниця становить **$\Delta = +0.0126$**, 95% CI **$[-0.0055, +0.0314]$** (перетинає нуль).
     * За **$F_2$-Score** при замороженому з Validation порозі $p^* = 0.129$ модель `Set C` поступається адаптивному бейзлайну: **$\Delta F_2 = -0.0133$**, 95% CI **$[-0.0223, -0.0048]$** (`0.6301` проти `0.6430`).

## 🛡️ Перевірка каузальної інваріантності та методичні обмеження

### Що перевіряє автотест `tests/test_leakage_invariance.py`
Скрипт перевіряє **відсутність дублікатів (`assert 0`)** у `alerts_clean_oblast.parquet` та `ml_features_hourly.parquet`, верифікує структуру всіх чотирьох наборів ознак (`Set A` — 10 ознак, `Set B` — 13 ознак, `Set C` — 22 ознаки, `Set C'` — 19 ознак, де `C' = C \ {national_active_count, hours_since_last_alert, onsets_last_24h}`), після чого бере **$119$ часових міток $T$** ($19$ граничних точок — початок сітки $k=0,1,2,3,6$, межі вікон $k=23,24,25,167,168,335,336,719,720$ та межі сплітів Train/Val/Test — плюс $100$ випадкових моментів $T$, загалом **`2 399` рядків область-година**) і виконує дві перевірки:
1. **Фізичне обрізання майбутнього на момент $T$:** з таблиці інтервалів видаляються всі тривоги з `started_at > T`, а для тривог, де `finished_at > T`, час завершення затирається (`NaT`, вважаються відкритими станом на $T$). На цих обрізаних даних з нуля перераховуються фільтр спокою `is_active_T == 0` та всі ознаки наборів A, B, C та C' (`lagged_onset_1h`, `burden_last_6h`, `burden_last_24h`, `adaptive_rate_7d/14d/30d`, `national_active_count`, `onsets_last_24h`, `hours_since_last_alert`, `neighbors_active_count`, `neighbor_any_active`, `neighbor_active_ratio`, `neighbors_active_lag_1h/2h/3h` та календарні цикли) і звіряються зі збереженим Feature Store.
2. **Перевірка вікна таргету $[T, T + 1\text{h})$:** перевіряється, що значення `target_onset_next_1h` у Feature Store збігається з індикатором наявності стартів тривог виключно у піввідкритому інтервалі $[T, T + 1\text{h})$.

### ⚠️ Методичні обмеження та застереження (Limitations)
1. **Пост-хок характер вибору `Set B` та `Set C'`:** головним заздалегідь визначеним порівнянням був `Set C` проти адаптивного бейзлайну (`Adaptive 14-day Rolling`). Висновок про перевагу `Set B` за PR-AUC та побудова `Set C'` без 3 зміщених ознак є результатами пост-хок аналізу після перегляду Test.
2. **Обмеження тесту інваріантності щодо `cleaner.py`:** автотест `tests/test_leakage_invariance.py` працює поверх вже очищеного датасету `alerts_clean_oblast.parquet`. Він гарантує каузальність генератора ознак `feature_store.py`, але **не перевіряє первинну обробку в `src/data/cleaner.py`** — зокрема відсіювання мікро-тривог ($< 60$ с) за різницею `finished_at - started_at` (де для тривоги, що почалася менш ніж за 60 с до $T$, факт її відсіювання спирається на час завершення) та об'єднання перетинних інтервалів.
3. **Агрегація районів і громад після 01.08.2025:** побудова обласної тривоги як об'єднання інтервалів усіх районів і громад області (`oblast`, `raion`, `hromada`) забезпечує неперервність часового ряду після реформи оповіщення, але змінює просторову чутливість ознак `national_active_count` та `hours_since_last_alert` (оскільки локальна тривога в одному прикордонному районі зараховується як активність області).
4. **Цензурування тривалості на межі Train:** у `generate_train_only_clusters()` тривалість тривог, які перетинають межу `2024-04-30 23:59:59 UTC`, обрізається по верхній межі Train, проте в описовій таблиці RQ2 (`regional_clusters_summary.csv`) використано повний період 2022–2026 рр.
5. **Використання Validation для early stopping і порогу $p^*$:** вибірка Validation використовується одночасно для ранньої зупинки градієнтного бустингу (`stopping_rounds=30` у LightGBM) та для вибору порогу класифікації $p^* = \arg\max F_2$.
6. **Межі сплітів у UTC:** хронологічне ділення на Train / Validation / Test задано за часом UTC (`2024-04-30 23:59:59 UTC` та `2025-05-31 23:59:59 UTC`), тоді як добові ознаки та таблиця Historical Lookup використовують часовий пояс `Europe/Kyiv`.

## 🚀 Швидкий старт (Quickstart)

### 1. Клонування та встановлення залежностей
```bash
git clone https://github.com/Yaroo-a/ukrainian-air-raid-sirens-analysis.git
cd ukrainian-air-raid-sirens-analysis
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Повний відтворюваний запуск пайплайну з нуля
```bash
# Етап 1: Очищення, агрегація інтервалів, циклічність, кластери (RQ2 + Train-only для ML) та маршрути
python src/data/cleaner.py
python src/features/cyclicity.py
python src/features/clustering.py
python src/features/propagation.py

# Етап 2: Генерація Feature Store, аналіз зсуву ознак, навчання бейзлайнів і моделей (A, B, C, C'), оцінка на Test
python src/features/feature_store.py
python src/features/analyze_feature_shift.py
python src/models/baselines.py
python src/models/train_models.py
python src/models/evaluate_test.py

# Перевірка цілісності артефактів та тест каузальної інваріантності
python tests/verify_pipeline.py
python tests/test_leakage_invariance.py
```

### 3. Інтерактивні Jupyter Notebooks
```bash
jupyter lab
```
* `notebooks/01_data_profiling_and_cleaning.ipynb` — профілювання сирих даних, дедуплікація та агрегація інтервалів.
* `notebooks/02_rq1_temporal_cyclicity.ipynb` — тижневі/добові ритми та тест Краскела-Волліса.
* `notebooks/03_rq2_regional_clustering.ipynb` — ієрархічна кластеризація регіонів.
* `notebooks/04_rq3_spatial_propagation_routes.ipynb` — аналіз крос-кореляцій між сусідами.
* `notebooks/05_ml_forecasting_experiment.ipynb` — результати ML-моделей (A, B, C, C'), аналіз зсуву ознак, Ablation Study та оцінка за підперіодами Test.
